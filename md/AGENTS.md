# AGENTS.md — 项目规则单一来源

本项目规则统一维护在本文件，所有 AI 工具共同读取

修改规则时只改本文件 + `ai-skills/` 下的 Skill。

## 通用编码准则

**最快的路径是一次做对；信息不足时，先问，再动手。**
> 准则偏向「稳健优先于速度」，琐碎任务自行判断。

### 核心原则
**这是商业项目，不容一点错误。当信息不足时，请直接提问！**

### 先思考，后编码
不臆测，不藏匿不确定。
- 说出假设；不确定就问。
- 有多种理解，全部列出，不擅自选一种。
- 有更简方案就提出，必要时反驳。

### 最小实现
用最少的代码解决问题，不写投机性内容。
- 不做需求之外的功能，不为一次性代码做抽象。
- 不加未被要求的灵活性 / 配置项。
- 不为不可能发生的场景写防御代码。
- 自检：资深工程师会嫌它过度设计吗？会，就简化。

### 目标驱动
先定义可验证的成功标准，再循环验证。
- 把任务转成可验证目标：「修 bug」→「先写复现测试，再让它通过」。
- 多步任务先列简要计划，每步配一个验证点。

## 本项目规则

### 禁止事项
- **禁止自行补全接口**：不得编造未被确认的接口路径、参数或返回结构。
- **禁止裸 axios**：不得使用 `axios.create()` 或裸 `axios`，按项目请求方法获取数据。
- **禁止手动清空弹窗数据**：在外层用 `v-if="visible"` 控制弹窗，而非手动清空。
- **禁止使用“==”**：使用更为确定的”===“做对比
- **少用 ref 获取 DOM**：尽量少用 `ref` 获取 DOM 或者组件做操作（），保证数据单向流`。
- **依赖注入命名**：有 `provide` 源的配对用 `provideXxx` / `injectXxx`，`useXxx` 只留给无 provide 源的纯 composable，禁止 `useInjectXxx` / `useProvideXxx`。
- **禁止使用any类型**: 若要使用，必须经用户同意
- **禁止大单文件**: 一个文件内容应该在500行以下，超过时必须拆分。比如拆分成多个对象，每个对象各自管理自己的方法
- **禁止不区分文件层级**: 不能所有文件放在一个文件夹中，需要清晰的层级区分，以便人类阅读

### 强制要求
- **改动前**：先运行 `git add .`。
- **包管理**：统一用 `pnpm`。
- **公用 API**：新增 `src/utils/` 函数或 `src/components/` 组件时，必须在 `ai-skills/` 同步添加或更新 Skill。
- **格式化**：只格式化改动的文件，禁止全局格式化：
  ```bash
  npx eslint --fix <file-path-1> <file-path-2>
  ```

### css scoped vs root 包裹
每个组件必须要配置独一无二的class 作为root class,当组建可能使用其他组件时，最好使用root class 包裹而不是用scoped,这样更容易对子组件改样式
```css
.xxx{
  // 这里面写具体内容
  .a {}
}
```

## 方案确认
当遇到用户的需求，不可避免的需要使用非稳定方案时，必须告诉用户。比如用户让完成程序："如果辱骂他人，就禁言"，实现用正则匹配。
